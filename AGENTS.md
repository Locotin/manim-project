# Repository Guidelines

## Project Structure & Module Organization
This repository is a minimal Manim project.
- `scene.py`: main animation source file (Manim `Scene` classes).
- `requirements.txt`: Python dependency list (`manim`).
- `README.md`: quick start usage.
- `.venv/`: local virtual environment (do not commit).
- `media/`: render outputs generated by Manim (do not commit unless explicitly needed).

As the project grows, place new scenes in a `scenes/` package (for example, `scenes/intro.py`) and keep reusable helpers in `utils/`.

## Build, Test, and Development Commands
Run from repository root:
- `python3 -m venv .venv`: create local virtual environment.
- `source .venv/bin/activate`: activate environment.
- `pip install -r requirements.txt`: install dependencies.
- `manim -pqh scene.py AnimacionBasica`: render the sample scene and preview it.
- `manim -pql scene.py AnimacionBasica`: faster low-quality preview.
- `python -m py_compile scene.py`: quick syntax check.

## Coding Style & Naming Conventions
- Follow PEP 8 with 4-space indentation.
- Use `snake_case` for variables/functions and `PascalCase` for `Scene` class names.
- Keep one scene class per conceptual animation block.
- Prefer explicit, descriptive class names (for example, `IntroTitleScene`, `VectorTransformScene`).
- Keep timeline logic readable: group related `self.play(...)` calls and use short waits.

## Testing Guidelines
There is no formal test suite yet.
- Minimum check before PR: `python -m py_compile scene.py`.
- For animation changes, render at least one preview command and confirm output in `media/`.
- If helper modules are added, introduce `pytest` tests under `tests/` using `test_*.py` naming.

## Commit & Pull Request Guidelines
Git history is not established in this directory yet, so use this convention going forward:
- Commit format: `type(scope): short summary` (example: `feat(scene): add intro animation`).
- Keep commits focused and small.
- PRs should include: purpose, files changed, render command used, and a screenshot or output path when visuals change.
- Link related issues/tasks when applicable.

## Security & Configuration Tips
- Never commit `.venv/`, large render artifacts, or local cache files.
- Pin dependencies in `requirements.txt` when reproducibility becomes important.
